# Как читать проект

Проект специально разделён по ролям файлов. Поэтому преподавателю можно открыть любой слой и сразу понять его назначение.

```text
models/    -> объекты предметной области
schemas/   -> данные, которые принимает API
services/  -> основная бизнес-логика
api/v1/    -> HTTP-методы REST API
routes/    -> HTML-страницы
core/      -> база данных, настройки и безопасность
templates/ -> HTML
static/    -> CSS и JavaScript
```

## 1. С чего начать

Рекомендуемый порядок изучения:

1. `app/main.py` — точка запуска FastAPI.
2. `app/core/database.py` — создание SQLite и таблиц.
3. `app/models/` — основные сущности.
4. `app/schemas/` — формат входных данных.
5. `app/services/` — что система делает с данными.
6. `app/api/v1/` — как действия становятся HTTP-запросами.
7. `app/routes/` — как открываются страницы сайта.
8. `app/templates/` и `static/` — внешний интерфейс.

## 2. Пример: вход пользователя

Пользователь открывает `/login`.

`routes/auth.py` показывает HTML-страницу.

JavaScript отправляет `POST /api/v1/auth/login`.

`api/v1/auth.py` принимает данные и передаёт их в `services/auth.py`.

`services/auth.py`:

1. ищет пользователя в SQLite;
2. проверяет пароль;
3. создаёт JWT;
4. возвращает токен.

Браузер сохраняет токен в `localStorage` и использует его в следующих запросах.

## 3. Пример: выдача книги

Запрос `POST /api/v1/loans/borrow` попадает в `api/v1/loans.py`.

API-файл почти ничего не решает сам:

```python
return loan_service.borrow_book(data, user)
```

Вся логика находится в `services/loan.py`:

1. найти читателя;
2. найти экземпляр;
3. проверить верификацию;
4. проверить доступность экземпляра;
5. проверить лимит книг;
6. создать выдачу;
7. изменить статус экземпляра;
8. создать уведомление.

Такой подход удобен для обучения: HTTP-код и бизнес-правила не смешиваются.

## 4. Почему здесь нет пустых заглушек

Файлы `models`, `schemas`, `services` и `routes` содержат реальный код. Пустыми остаются только обычные `__init__.py`-файлы пакетов; в них добавлены короткие описания, чтобы они тоже были понятны.

## 5. Важная оговорка

База данных в проекте работает через стандартный `sqlite3`. Это проще для учебного проекта и не меняет внешний REST API или работу сайта. Названия слоёв сохранены в соответствии со структурой из ТЗ.
