## Проведённая проверка

После перехода требуется повторить на чистой PostgreSQL-БД:

- запуск Uvicorn и инициализацию схемы;
- `GET /health` → 200;
- `GET /api/v1/books` → 200;
- регистрация валидного читателя → 200;
- отклонение некорректного email → 422;
- вход начального администратора → 200 и JWT;
- `GET /api/v1/users/me` без JWT → 401;
- тот же запрос с JWT → 200.

## Что показать на защите

1. Открыть задачу, по которой реализовывалась выбранная функция.
2. Показать её ветку и несколько осмысленных коммитов.
3. Открыть обсуждение и результат слияния PR/MR.
4. Показать commit разрешения заранее подготовленного конфликта.
5. Выполнить `git tag --list --format='%(refname:short) %(subject)'` и показать `v0.1.0` и `v0.1.1`.
6. Показать `.gitignore`, затем убедиться через `git status`, что `.env` и `.venv` не отслеживаются.
7. Запустить приложение по README и продемонстрировать `/health`, регистрацию, вход и один связанный сценарий.

## Перед созданием тега

- заменить примеры в `.env` собственными локальными значениями, не добавляя `.env` в Git;
- выполнить команды проверки из README;
- проверить отсутствие секретов в diff и истории;
- убедиться, что документация соответствует фактическим endpoint;
- создать `v0.1.1` только на принятом PostgreSQL-состоянии основной ветки.
