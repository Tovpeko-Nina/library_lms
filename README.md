## Правила внесения изменений

### Ветки

Основная ветка проекта:

- `main` — стабильная версия.

Для разработки используются отдельные ветки:

- `feature/<name>` — новая функциональность;
- `fix/<name>` — исправление ошибки;
- `docs/<name>` — изменение документации.

### Формат коммитов

Используется формат:

`type: description`

Примеры:

- `feat: add book search`
- `fix: correct loan calculation`
- `docs: update API description`
- `refactor: simplify book service`
- `chore: update dependencies`

### Проверка перед коммитом

Перед коммитом необходимо:

1. проверить запуск приложения;
2. проверить `/health`;
3. проверить изменённую функциональность;
4. убедиться, что `.env` и локальная БД не добавлены в Git.

### Запрещено

Не добавлять в репозиторий:

- `.env`;
- пароли и секретные ключи;
- `.venv`;
- `__pycache__`;
- локальные базы данных;
- временные файлы.

### Порядок принятия изменений

1. Создать отдельную ветку.
2. Внести изменения.
3. Выполнить проверку.
4. Сделать осмысленные коммиты.
5. Отправить ветку на удалённый репозиторий.
6. Создать Pull Request / Merge Request.
7. Проверить изменения.
8. Выполнить слияние в `main`.


## Local development

1. Create a virtual environment.
2. Install dependencies.
3. Configure `.env`.
4. Run the application.
